==== UE-Initiated Detach Procedure

===== Technical Overview

The UE-initiated Detach procedure lets a UE inform the network that it no
longer needs access to the Evolved Packet System (EPS), and it deactivates
all active EPS bearer contexts, including the default bearer.

The procedure removes the UE's mobility management and security contexts
from the MME and from the UE, moving the UE to the EMM-DEREGISTERED state.

Across the S1, S11, and S5/S8 interfaces, the Evolved Packet Core (EPC)
releases all associated user-plane and control-plane resources.

===== Call Flow

The call flow has three phases: Detach Request, Resource Deactivation, and
Detach Acceptance and S1 Release.

===== Step-by-Step Description

. The *UE* sends a `Detach Request` message to the *eNodeB*, carrying this
NAS message inside an RRC message; if the UE was in ECM-IDLE mode, this
message triggers the establishment of a NAS signalling connection. The
message carries the GUTI, the Detach type, which shows the kind of
detach, for example EPS detach or combined EPS/IMSI detach, the Switch
off indicator, which shows whether the UE is powering down, and the NAS
key set identifier (eKSI).

. The *eNodeB* forwards the NAS message to the *MME* inside an S1AP
`Uplink NAS Transport` message, including the User Location Information
of the serving cell, that is the ECGI and the TAI, and the NAS-PDU.

. If Idle mode Signalling Reduction (ISR) is active for the UE, the *MME*
sends a GTPv2 `Detach Notification` message to the associated *SGSN* to
detach the UE from GERAN/UTRAN access as well. The message carries a
Cause value set to "Complete Detach" and the Detach Type.

. On receiving the Detach Notification, the *SGSN* deactivates the UE's
active Packet Data Protocol (PDP) contexts and sends a GTPv2 `Delete
Session Request` message to the *S-GW*. The message carries the LBI, the
User Location Information, that is the Cell Global Identity (CGI) and the
Service Area Identity (SAI), and the UE Time Zone.

. The *S-GW* acknowledges the deletion of the SGSN-related bearer
contexts by returning a GTPv2 `Delete Session Response` message, carrying
a Cause, to the *SGSN*.

. The *SGSN* confirms the completion of its local detach procedure by
sending a GTPv2 `Detach Acknowledge` message, carrying a Cause, to the
*MME*.

. To deactivate all active EPS bearers, the *MME* sends a GTPv2 `Delete
Session Request` message to the *S-GW* for each PDN connection, carrying
the LBI, the User Location Information (ECGI), the Secondary RAT usage
data, and the UE Time Zone. If ISR was active, the S-GW does not release
its control-plane TEID until it receives this message.

. For each PDN connection that the procedure releases, the *S-GW* sends a
GTPv2 `Delete Session Request` message to the *P-GW*, telling the P-GW to
delete all bearers for that PDN connection. The message carries the LBI,
the User Location Information, and the Secondary RAT usage data.

. If the network deploys dynamic PCC, the *P-GW* starts an IP-CAN Session
Termination procedure with the *PCRF*, using Diameter, letting the PCRF
release the policy and charging rules for the session. The Diameter
message carries a CC-Request-Type set to TERMINATION_REQUEST and the
Used-Service-Unit, for usage monitoring reporting.
<<_pcc_ip_can_session_termination>> describes this procedure in detail.

. The *P-GW* acknowledges the session deletion by returning a GTPv2
`Delete Session Response` message to the *S-GW*, carrying a Cause and the
APN Rate Control Status.

. The *S-GW* releases the UE's context information and forwards the
acknowledgement to the *MME* with a GTPv2 `Delete Session Response`
message, carrying a Cause and the APN Rate Control Status.

. If the UE indicated that Switch off is false in the Detach Request, the
*MME* sends a NAS `Detach Accept` message to the *eNodeB* inside an S1AP
`Downlink NAS Transport` message, carrying the NAS-PDU and the MME UE
S1AP ID.

. The *eNodeB* delivers the Detach Accept message to the *UE* over the
radio interface, and the UE stops timer T3421 on receiving it.

. The *MME* starts the release of the S1-MME signalling connection by
sending an S1AP `UE Context Release Command` message to the *eNodeB*,
carrying the UE S1AP IDs and a Cause set to "Detach".

. The *eNodeB* sends an RRC `Connection Release` message to the *UE* and
deletes the UE's RAN context after the UE acknowledges it.

. The *eNodeB* confirms the release of the S1 connection and the
user-plane resources by sending an S1AP `UE Context Release Complete`
message to the *MME*, carrying the MME UE S1AP ID, the eNB UE S1AP ID,
and the User Location Information.

===== Possible Failures and Required Actions

Authentication failure during S1 establishment:: When the UE is in
ECM-IDLE mode, it first needs to set up the S1 connection to send the
Detach Request, and the MME can start authentication at that point. If
authentication fails, the UE receives a NAS `Authentication Reject`
message, stops the Detach procedure, stops all related EMM timers, for
example T3421, and enters the EMM-DEREGISTERED state. The MME can
deactivate all non-emergency bearers and mark the UE as detached.

Detach through an unauthorized CSG cell:: The UE can send a Detach
Request, without the Switch off indicator, while connected to a Closed
Subscriber Group (CSG) cell for which its subscription has expired. In
this case, the MME responds with EMM Cause #25, "Not authorized for this
CSG", and starts a network-initiated detach procedure. The UE removes the
CSG ID from its Allowed CSG list and, if needed, performs a new Public
Land Mobile Network (PLMN) selection.

T3421 timer expiry:: The UE can send a Detach Request, without the Switch
off indicator, and not receive a Detach Accept message before timer
T3421 expires. In this case, the UE retransmits the Detach Request
message, up to four times, and on the fifth expiry stops the signalling
procedure, performs a local detach, and enters the EMM-DEREGISTERED
state.
