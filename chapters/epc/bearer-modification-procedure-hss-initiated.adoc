==== HSS-Initiated Subscribed QoS Modification Procedure

===== Technical Overview

The HSS-initiated Subscribed QoS Modification procedure updates the QoS
of an active EPS bearer after a change in the subscriber's subscription
data at the Home Subscriber Server (HSS), and the HSS starts the
procedure.

The procedure changes the Subscribed UE Aggregate Maximum Bit Rate
(Subscribed-UE-AMBR), the Subscribed APN-AMBR, or the QCI and the ARP of
the default bearer.

The procedure synchronizes the UE's radio and session management
contexts with the new subscription parameters across the MME, the
S-GW, and the P-GW, keeping the bearer compliant with the PCC rules.

===== Call Flow

The call flow has three phases: Subscription Update, Bearer Modification
Command, and, if the QCI, the ARP, or the APN-AMBR changed, Bearer
Modification Request and Bearer Modification Acknowledgement.

===== Step-by-Step Description

. After an administrative change to the subscription, the *HSS* starts
the procedure by sending a Diameter `Insert-Subscriber-Data-Request`
(IDR) message to the *MME*, carrying the IMSI and the Subscription-Data,
that is the new Subscribed-UE-AMBR, APN-AMBR, QCI, or ARP.

. The *MME* updates its local UE context with the new subscription data
and returns a Diameter `Insert-Subscriber-Data-Answer` (IDA) message to
the *HSS*, carrying a Result-Code set to DIAMETER_SUCCESS.

. If the new subscription data affects an active PDN connection, for
example a changed QCI or APN-AMBR, the *MME* sends a GTPv2 `Modify
Bearer Command` message to the *S-GW*, carrying the EBI of the default
bearer, the Bearer Level QoS, and the APN-AMBR.

. The *S-GW* forwards the GTPv2 `Modify Bearer Command` message to the
*P-GW*, carrying the EBI, the Bearer Level QoS, and the APN-AMBR.

. If the network deploys dynamic PCC, the *P-GW* reports the updated
subscribed QoS to the *PCRF* by sending a Diameter `Credit-Control-Request`
(CCR) message over the Gx interface, with the CC-Request-Type set to
UPDATE_REQUEST, carrying the Subscription-Id, the QoS-Information, and
the APN-Aggregate-Max-Bitrate.

. The *PCRF* authorizes the modification, adjusting the parameters
based on local policy if needed, and returns a Diameter
`Credit-Control-Answer` (CCA) message to the *P-GW*, carrying a
Result-Code, the QoS-Information, and the APN-Aggregate-Max-Bitrate.
<<_pcc_ip_can_session_modification_pcef_initiated>> describes the
PCEF-initiated IP-CAN Session Modification in detail.

. To update the bearer context, the *P-GW* sends a GTPv2 `Update Bearer
Request` message to the *S-GW*, carrying the EBI, the Bearer Level QoS,
the TFT, and the APN-AMBR.

. The *S-GW* forwards the GTPv2 `Update Bearer Request` message to the
*MME*, without changes.

. The *MME* builds a NAS `Modify EPS Bearer Context Request` message
and sends it to the *eNodeB* inside an S1AP `E-RAB Modify Request`
message, carrying the E-RAB ID, the E-RAB Level QoS Parameters, the
NAS-PDU, and the UE-AMBR.

. The *eNodeB* reconfigures the radio bearer by sending an RRC
`Connection Reconfiguration` message to the *UE*, carrying the Radio
Bearer QoS and the Session Management Request.

. The *UE* confirms the successful reconfiguration of its radio
resources by returning an RRC `Connection Reconfiguration Complete`
message to the *eNodeB*.

. The *eNodeB* informs the MME of the outcome of the resource
modification by returning an S1AP `E-RAB Modify Response` message to
the *MME*, carrying the E-RAB ID and a Cause set to "Request Accepted".

. The *UE* accepts the new EPS bearer context by sending a NAS `Modify
EPS Bearer Context Accept` message, carrying the EBI, inside an RRC
`Direct Transfer` message, to the *eNodeB*, which forwards it to the
*MME* inside an S1AP `Uplink NAS Transport` message.

. When the *MME* receives both the eNodeB and the UE acknowledgements,
it sends a GTPv2 `Update Bearer Response` message to the *S-GW*,
carrying the EBI, a Cause set to "Request Accepted", and the ULI.

. The *S-GW* forwards the GTPv2 `Update Bearer Response` message to the
*P-GW*, carrying the EBI, the Cause, and the ULI.

. If the network deploys dynamic PCC and the PCRF requested a
confirmation of the resource allocation (TS 29.212 clause 4.5.2.0), the
*P-GW* confirms the enforcement of the authorized QoS to the *PCRF* by
sending a Diameter
`Credit-Control-Request` (CCR) message, with the Event-Trigger set to
SUCCESSFUL_RESOURCE_ALLOCATION, and the PCRF returns a Diameter
`Credit-Control-Answer` (CCA) message to acknowledge the final status.

===== Possible Failures and Required Actions

HSS registration rejection:: If the MME sends an Update Location for a
subscriber unknown to the HSS, the HSS returns a Diameter Result-Code
DIAMETER_ERROR_USER_UNKNOWN (5001). When the HSS returns this error
during an Update Location, the MME rejects the UE's Attach or Tracking
Area Update request, with EMM Cause #2, "IMSI unknown in HSS", whereas
when it returns this error during an Insert Subscriber Data procedure
for an active UE, the MME locally detaches the UE and removes its
context.

Radio resource allocation rejection by eNodeB:: If the eNodeB cannot
provide the requested GBR or QCI because of congestion, it returns an
S1AP Cause #20, "Radio resources not available", or a cause of "Not
supported QCI Value". The MME maps this to GTPv2 Cause #89, "Service
denied", or GTPv2 Cause #90, "No resources available", in the `Update
Bearer Response` message to the P-GW, which informs the PCRF that the
modification failed and, if the modification is mandatory, can delete
the affected bearer.

NAS syntactical error in the TFT:: If the UE's NAS layer finds a syntax
error in the packet filters of the modification request, the UE returns
a NAS `Modify EPS Bearer Context Reject` message, with ESM Cause #45,
"syntactical error in the TFT operation", which maps to GTPv2 Cause
#77, "Syntactic errors in packet filter(s)". The MME stops timer
T3486, aborts the procedure, and can start a procedure to re-align the
bearer context between the EPC and the UE.
