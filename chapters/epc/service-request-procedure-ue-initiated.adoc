==== UE-Initiated Service Request Procedure

===== Technical Overview

The UE-initiated Service Request procedure lets a UE in ECM-IDLE mode
establish a Non-Access Stratum (NAS) signalling connection with the
network. The UE starts this procedure when it has pending uplink user
data or pending uplink signalling.

The procedure establishes the radio bearers and the S1 user-plane bearers
for the UE's active EPS bearers. The procedure moves the UE from
ECM-IDLE mode to ECM-CONNECTED mode.

The procedure synchronizes the EPS bearer contexts between the UE and
the MME.

===== Call Flow

The call flow has three phases: Service Request, Radio Bearer Setup, and
Path Switch and Data Delivery.

===== Step-by-Step Description

. The *UE* sends a `Service Request` message to the *eNodeB*. The UE
sends this NAS message inside the RRC connection establishment
procedure. The message carries the NAS key set identifier (KSI), the NAS
sequence number, and the NAS Message Authentication Code (NAS-MAC).

. The *eNodeB* forwards the NAS message to the *MME* inside an S1AP
`Initial UE Message`. This message establishes the UE-associated logical
S1 connection. The message carries the NAS-PDU, the S-TMSI, the TAI and
the E-UTRAN Cell Global Identifier (ECGI) of the serving cell, and the
RRC establishment cause, for example "mo-Data" or "mo-Signalling".

. The UE's security context can be missing or no longer valid. In this
case, the *MME* and the *UE* perform the Authentication and Security
Procedures. These procedures carry the RAND, the AUTN, and the selected
NAS security algorithms. They activate NAS integrity protection and
ciphering.

. The *MME* sends an S1AP `Initial Context Setup Request` message to the
*eNodeB*. This message provides the eNodeB with the security context and
the Serving GW address for the uplink. The message carries the MME UE
S1AP ID, the eNB UE S1AP ID, the E-RAB To Be Setup List, with the S1-U
S-GW Fully Qualified Tunnel Endpoint Identifier (F-TEID) and the QoS
parameters, the UE Aggregate Maximum Bit Rate, and the Security Context.

. The *eNodeB* sets up the radio bearer. The eNodeB sends an RRC
`Connection Reconfiguration` message to the *UE*, to establish the data
radio bearers for the requested E-RABs.

. The *UE* completes the radio reconfiguration. The UE returns an RRC
`Connection Reconfiguration Complete` message to the *eNodeB*. The UE is
now ready to send user data.

. The *eNodeB* sends an S1AP `Initial Context Setup Response` message to
the *MME*. This message provides the MME with the eNodeB's downlink
tunnel information. The message carries the eNB UE S1AP ID, the MME UE
S1AP ID, and the E-RAB Setup List, with the S1-U eNodeB F-TEID for the
downlink.

. The *eNodeB* can forward uplink user-plane packets to the *S-GW*,
using the S-GW F-TEID from step 4, once the radio bearer setup
completes.

. The *MME* sends a GTPv2 `Modify Bearer Request` message to the *S-GW*,
for each PDN connection, to update the user-plane path with the
eNodeB's downlink F-TEID. The message carries the Bearer Contexts to be
modified, that is the EPS Bearer Identity (EBI) and the S1-U eNodeB
F-TEID, the User Location Information, and the RAT type.

. The network can deploy dynamic Policy and Charging Control (PCC). In
this case, the *S-GW* forwards the GTPv2 `Modify Bearer Request` message
to the *P-GW*. The P-GW starts a Diameter `Credit-Control-Request`/
`Credit-Control-Answer` (Update) exchange with the *PCRF* over the Gx
interface. The Diameter message carries the CC-Request-Type set to
UPDATE_REQUEST, the 3GPP-User-Location-Info, and the RAT-Type. The P-GW
returns a GTPv2 `Modify Bearer Response` message to the S-GW.

. The *S-GW* returns a GTPv2 `Modify Bearer Response` message to the
*MME*, carrying a Cause set to "Request Accepted" and the S-GW F-TEID
for the control plane. The S-GW sends this message whether or not the
network deployed dynamic PCC.

. The *S-GW* delivers buffered or newly arrived downlink user data to
the *eNodeB*, using the downlink F-TEID from step 7. The eNodeB delivers
the data to the *UE* over the radio interface.

===== Possible Failures and Required Actions

Authentication failure:: The UE fails the authentication check that the
MME starts during the Service Request procedure. The MME sends a NAS
`Authentication Reject` message, with EMM Cause #3, "Illegal UE", or EMM
Cause #6, "Illegal ME". The UE stops the procedure, considers its USIM
or SIM invalid for EPS services, and enters the EMM-DEREGISTERED state.

MME congestion:: The MME is overloaded and cannot process the Service
Request. The MME sends a NAS `Service Reject` message, with EMM Cause
#22, "Congestion", and a value for timer T3346. The UE starts timer
T3346 and does not start a new Service Request of the same category
until the timer expires.

E-UTRAN resource allocation failure:: The eNodeB cannot admit one or
more E-RABs, because radio resources are not available. The eNodeB
returns an S1AP `Initial Context Setup Failure` message, with S1AP
Cause "Radio resources not available". The MME maps this internally to
GTP Cause #73, "No resources available", and can map it further to NAS
EMM Cause #26, "Insufficient resources", if the MME rejects the UE. The
MME locally deactivates the EPS bearer contexts that failed to
establish. The UE stays in its current state and can start timer
T3346.
