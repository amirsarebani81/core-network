==== HSS-Initiated Detach Procedure

===== Technical Overview

The HSS-initiated Detach procedure lets the HSS remove a subscriber's MM
context and EPS bearer contexts from the network; the HSS, not the UE,
triggers this procedure.

The HSS starts the procedure for operator-determined reasons, for example
a subscription withdrawal, a profile change that no longer allows
Packet-Switched (PS) services, or a Core Network access restriction.

The procedure removes the contexts from the MME and, if the network
deploys an SGSN for the subscriber, from the SGSN as well.

The procedure moves the UE to the EMM-DEREGISTERED state and releases all
active PDN connections and their EPS bearers, and the MME, the S-GW, and
the P-GW remove the subscriber's session information.

===== Call Flow

The call flow has four phases: Cancellation at the MME, UE Notification,
Resource Release, and Detach Acknowledgement and S1 Release.

===== Step-by-Step Description

. The *HSS* starts the procedure by sending a Diameter
`Cancel-Location-Request` (CLR) message to the *MME*, asking the MME to
delete the subscriber's MM context and EPS bearer contexts. The message
carries the IMSI, the Cancellation-Type, for example "Subscription
Withdrawal", and, optionally, the CLR-Flags, including a
Reattach-Required indicator.

. The *MME* verifies the IMSI and confirms that it accepted the
cancellation by returning a Diameter `Cancel-Location-Answer` (CLA)
message to the *HSS*, carrying a Result-Code and the Supported-Features.

. If the UE is in ECM-IDLE mode, the *MME* starts the Paging procedure by
sending an S1AP `Paging` message to the *eNodeB*, carrying the UE
Identity Index Value, the Paging Discontinuous Reception (DRX) cycle, and
the S-TMSI, and the eNodeB pages the *UE* over the radio interface with
an RRC `Paging` message.

. The *UE* responds to the page with an RRC `Service Request` message to
the *eNodeB*, which forwards the request to the *MME* inside an S1AP
`Initial UE Message`, carrying the Service Request; this exchange
establishes a NAS signalling connection.

. The *MME* sends a NAS `Detach Request` message to the *eNodeB* inside
an S1AP `Downlink NAS Transport` message, carrying the Detach type,
which shows whether the UE needs to reattach, and an EMM cause, for
example cause #2, "IMSI unknown in HSS". The eNodeB delivers the Detach
Request to the *UE* inside an RRC `Downlink Direct Transfer` message,
telling the UE that the network detached it.

. To deactivate the associated EPS bearers, the *MME* sends a GTPv2
`Delete Session Request` message to the *S-GW* for each active PDN
connection, carrying the LBI, the User Location Information (ECGI), and,
if policy permits, the NAS Release Cause.

. For each PDN connection that the procedure releases, the *S-GW*
forwards the GTPv2 `Delete Session Request` message to the *P-GW*,
carrying the LBI, the User Location Information, and the Indication
Flags, with the Operation Indication flag set.

. If the network deploys dynamic PCC, the *P-GW* starts an IP-CAN
Session Termination procedure with the *PCRF* by sending a Diameter
`Credit-Control-Request` (CCR) message to report the final usage,
carrying a CC-Request-Type set to TERMINATION_REQUEST, the
Subscription-Id, and the Used-Service-Unit.

. The *PCRF* acknowledges the termination by returning a Diameter
`Credit-Control-Answer` (CCA) message, carrying a Result-Code, to the
*P-GW*, letting the P-GW release the session's policy and charging
resources. <<_pcc_ip_can_session_termination>> describes this procedure
in detail.

. The *P-GW* acknowledges the deletion by returning a GTPv2 `Delete
Session Response` message to the *S-GW*, carrying a Cause set to
"Request Accepted" and the APN Rate Control Status.

. The *S-GW* releases its local context for the UE and returns a GTPv2
`Delete Session Response` message to the *MME*, carrying a Cause and the
Recovery counter.

. The *UE* acknowledges the Detach Request with a NAS `Detach Accept`
message to the *eNodeB* inside an RRC `Direct Transfer` message, and the
eNodeB forwards it to the *MME* inside an S1AP `Uplink NAS Transport`
message, carrying the NAS-PDU and the User Location Information.

. When the *MME* receives both the Detach Accept and the Delete Session
Response, it starts the release of the S1-MME signalling connection by
sending an S1AP `UE Context Release Command` message to the *eNodeB*,
carrying the UE S1AP IDs and a Cause set to "Detach".

. The *eNodeB* sends an RRC `Connection Release` message to the *UE* and
deletes the UE's RAN context after the UE acknowledges it.

. The *eNodeB* confirms the release of the S1 connection by sending an
S1AP `UE Context Release Complete` message to the *MME*, carrying the
MME UE S1AP ID and the eNB UE S1AP ID.

===== Possible Failures and Required Actions

T3422 timer expiry:: The MME sends the Detach Request and starts timer
T3422, with a default value of 6 seconds. If the MME does not receive a
Detach Accept message before the timer expires, it retransmits the
Detach Request, up to four times, and on the fifth expiry stops the
signalling procedure and enters the EMM-DEREGISTERED state for the UE.

Detach in a forbidden satellite E-UTRAN area:: In a network that uses
satellite E-UTRAN access, the MME can determine that the UE is in a
location where the PLMN cannot operate. In this case, the MME sends the
Detach Request with EMM Cause #78, "PLMN not allowed to operate at the
present UE location", and the UE enters the EMM-DEREGISTERED.LIMITED-SERVICE
state and searches for a new suitable cell.

Detach procedure collision:: The UE can start a UE-initiated Detach
procedure, for example due to power off, while an HSS-initiated Detach
procedure is in progress at the MME, sending a Detach Request with the
Switch off indicator before the MME completes the HSS-initiated
procedure. In this case, the MME considers both Detach procedures
complete at the same time.
